# 必要API洗い出し

## 目的

このドキュメントは、Figmaの画面要件をもとに、HangWatで必要なAPIを整理するための設計書である。

フロントエンド担当とバックエンド担当が、以下について共通認識を持つことを目的とする。

- どの画面でどのAPIを使うか
- 画面表示に必要なデータは何か
- ユーザー操作に対して必要なAPIは何か
- Request / Response の形式
- APIで扱う主要なデータ型
- 認証・認可のルール
- MVPで優先して実装するAPI

## 共通ルール

| 項目 | ルール |
| --- | --- |
| リクエスト形式 | JSON |
| レスポンス形式 | JSON |
| 日時形式 | ISO 8601 |
| ID形式 | string |
| 認証方式 | ログインセッション、またはトークン認証を想定 |
| 未ログイン | 401を返す |
| 権限なし | 403を返す |
| データなし | 404を返す |

---

## 認証・認可の分類

| 表記 | 意味 |
| --- | --- |
| 不要 | ログインもイベント参加も不要 |
| ログイン必須 | `users` としてログインしている必要がある |
| イベント参加者 | ログインユーザーまたはURL参加者として、対象イベントの `event_members` に存在する必要がある |
| owner | 対象イベントの `event_members.role = owner` である必要がある |
| 本人 | 対象データを作成した `event_member` 本人である必要がある |
| 本人またはowner | 作成者本人、またはイベントownerである必要がある |

URL参加者は `users` には作成せず、`event_members` にのみ作成する。

そのため、予定候補作成、コメント投稿、コメントいいねなどのイベント内操作は、ログインユーザーではなく `event_members` を基準に認可する。

## 共通エラーコード

| Status | Code | 説明 |
| --- | --- | --- |
| 400 | VALIDATION_ERROR | 入力値が不正 |
| 401 | UNAUTHORIZED | 未ログイン |
| 403 | FORBIDDEN | 権限なし |
| 404 | NOT_FOUND | データが存在しない |
| 409 | CONFLICT | 競合 |
| 500 | INTERNAL_SERVER_ERROR | サーバーエラー |

## 設計メモ

Event と ScheduleCandidate は分けて扱う。

Event はイベント全体を表す。

例：

- 昼ごはん会
- 居酒屋
- パークゴルフ

ScheduleCandidate はイベント内の具体的な予定候補を表す。

例：

- 13:00 一蘭
- 14:00 梅田
- 18:00 居酒屋A

この2つを分けることで、1つのイベントに複数の予定候補を持たせられる。

また、後から以下の機能を追加しやすくなる。

- 複数候補
- 投票
- 参加可否
- 予定確定
- リマインダー
- 招待リンク

## URL参加者の扱い

URL参加者は `users` には作成しない。

招待URLから参加するユーザーは、表示名のみを入力して `event_members` に登録する。

ログインユーザーもURL参加者も、イベント内では `EventMember` として扱う。

コメント、いいね、予定候補作成者は `user_id` ではなく `event_member_id` を基準に扱う。

---

## Google Maps場所情報の扱い

イベントと予定候補の場所は、文字列だけでなく `Location` 型として扱う。

MVPでは、Google Maps URLから場所情報を取得できるAPIを優先する。

Google Placesの候補検索や詳細取得は、必要に応じて追加する。
