# Pull Request ルール

Pull Request はレビュー可能な単位で作成します。
実装内容だけでなく、確認方法と影響範囲を明確にします。

## PR のサイズ

- 1 PR は 1 Issue または 1 目的に寄せる。
- 目安として、レビュー対象が大きくなりすぎる場合は分割する。
- リファクタリングと機能追加はできるだけ別 PR にする。

## PR に書く内容

- 何を変更したか
- なぜ変更したか
- どう確認したか
- 影響範囲
- 関連 Issue

## レビュー観点

- 要件を満たしているか
- 責任分離が崩れていないか
- 命名が意図を表しているか
- 不要な抽象化や重複がないか
- エラーケースを扱っているか
- テストまたは手動確認が十分か
- ドキュメント更新が必要な変更か

## マージ前チェック

- `pnpm build` が成功する。
- フロントエンド変更がある場合は `pnpm lint` が成功する。
- DB schema 変更がある場合は migration が含まれている。
- API 変更がある場合は README または関連 docs を更新する。
